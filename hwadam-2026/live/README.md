# 2026 화담집 편집실 — 공동 제출 운영판

Google Apps Script, Google 로그인, 유료 OCR API 없이 운영합니다. OCR은 사진앱이나 외부 사이트에서 수행하고 추출한 글을 붙여넣습니다. 원고는 Sites에 연결된 D1 공용 저장소에 기록합니다. 별도 서버를 교사가 설치할 필요는 없습니다.

## 사용

1. 선생님이 사이트에서 **선생님 원고 관리함**을 엽니다. 필요하면 현재 사이트 소유자의 ChatGPT 계정으로 인증합니다. 학생에게는 이 계정이나 원고 관리함 접근 권한을 주지 않습니다.
2. 관리함에서 **제출 링크 복사**를 눌러 편집위원들에게 전달합니다.
3. 편집위원은 제출 링크를 열어 Google·ChatGPT 계정 없이 원고를 입력하고 제출합니다. 원고를 열람하거나 수정할 권한은 없습니다.
4. 관리자는 목록을 새로고침하여 원고를 확인하고 수정·상태 변경·전체 복사를 합니다. 복사 순서는 목차 / 작성자 학번·이름 / 제목 / 담당 편집위원 / 빈 줄 / 본문입니다. 다운로드 기능은 없습니다.
5. 목록 또는 상세 화면의 **반영완료** 체크박스로 실제 문집 편집에 옮겼는지 표시합니다. 체크/해제는 즉시 저장되며 ‘편집 완료’ 검토 상태와 별개입니다. 미저장 본문 교정은 그대로 유지됩니다.
6. **새 제출 링크 만들기**는 이전 제출 링크를 무효화합니다. 이미 제출된 원고는 유지됩니다.

## 입력과 OCR

- 입력 네 줄: 목차, 작성자 학번·이름, 원고 제목, 담당 편집위원.
- 원고 40,000자 이하. 사진은 선택이며 교정용으로 브라우저에서만 표시·압축합니다. 사진은 서버에 전송하거나 저장하지 않습니다.
- 외부 OCR은 별도 사이트입니다. 이 사이트가 자동 업로드·추출을 하지 않습니다. 본문을 복사해 붙여넣습니다.
- 제출 실패 시 탭의 sessionStorage에 원고와 접수 번호가 유지됩니다. 같은 번호로 재시도하면 중복 저장을 막습니다. 장기 초안 보존은 보장하지 않으므로 중요한 글은 ‘작성 중인 원고 복사’로 별도 보관하세요.
- 기존 체험판에 브라우저별로 저장한 원고는 공동 저장소로 자동 전송하지 않습니다. 예시 원고도 넣지 않습니다.

## 접근과 개인정보

- 제출 화면은 계정 없이 열 수 있지만, 유효한 제출 링크의 비밀 코드를 요청 헤더에 제시해야 제출됩니다. 링크의 코드는 처음 열 때 주소에서 제거하고 해당 탭에만 보관합니다. 초대 링크는 편집위원에게만 공유하세요.
- 초대 링크 소유자는 원고 제출만 가능합니다. 학생용 코드로 원고 목록·본문 조회, 수정, 초대 링크 조회·변경은 불가능합니다.
- 관리자 API는 매 요청마다 Sites가 검증하여 주입한 ChatGPT 사용자 ID를 확인합니다. 브라우저가 임의로 보내는 신원 헤더를 신뢰해서는 안 되며 Sites의 인증 경계를 전제로 운영합니다.
- 최초 관리자만 서버 비밀 `BOOTSTRAP_ADMIN_EMAIL`과 검증된 로그인 이메일을 일치시켜 등록합니다. 등록 후에는 사이트 범위에서 고정된 사용자 ID로 권한을 검사합니다. 두 번째 계정은 같은 이메일을 제시해도 자동 관리자가 되지 않습니다.
- 관리자 나가기는 해당 사이트의 ChatGPT 인증도 종료하도록 연결되어 있습니다. 공용 기기에서는 탭도 닫으세요.
- 공용 제출 링크는 개별 학생 신원을 보증하지 않습니다. 작성자·편집위원은 직접 입력 정보입니다.
- 본문에 필요한 것 이상의 개인정보를 적지 마세요. 외부 OCR에는 학번·이름을 가리고 본문만 올리세요.
- 제출 남용 완화: IP를 직접 저장하지 않고 시간 구간과 결합한 해시로 시간당 40회 제한. 같은 접수 번호 재확인은 횟수 제한 후에도 허용합니다. 여러 학생이 같은 학교 네트워크를 쓸 경우 같은 한도가 적용될 수 있습니다.

## 개발

- `web/index.html`: 화면 원본
- `worker/index.mjs`: 서버 원본. 빌드시 HTML을 한 모듈로 포함
- `drizzle/0000_editorial.sql`: D1 스키마. 적용된 마이그레이션을 수정하지 말고 새 마이그레이션을 추가
- `.openai/hosting.json`: 기존 Site ID와 D1 연결 선언
- `build.mjs`: 서버·화면·마이그레이션 패키징
- `tests/server.test.mjs`: SQLite에서 실제 SQL을 실행하는 서버 테스트
- `tests/ui.test.mjs`: Chromium의 서로 분리된 학생/교사 브라우저로 실제 로컬 HTTP 서버 흐름 확인

`npm run build`, `npm test`. 브라우저 테스트의 Playwright/Chromium 설치 경로는 실행 환경에 맞게 변경합니다. 로컬 테스트의 교사 헤더 주입은 테스트 서버에만 있으며 운영 Worker에 포함되지 않습니다.

환경 변수 값과 실제 원고는 Git에 저장하지 않습니다. 코드 소유권·호스팅 접속 권한과 원고 관리 권한을 구분합니다. 학생용 제출 링크를 공개 GitHub에 올리지 마세요.

## 공개 설정

학생이 Google·ChatGPT 계정 없이 접속하도록 사이트의 접속 범위를 링크 공개로 전환하도록 사용자가 명시적으로 승인했습니다. 공개 페이지는 입력 화면이며, 제출에는 유효한 전용 링크 코드가 필요합니다. 관리자 API는 계속 검증된 선생님 계정만 허용합니다. 이 승인 없이 공개 범위를 임의로 확장하지 않습니다.

검증: 로컬 실제 SQLite와 서로 분리된 Chromium 브라우저에서 공동 제출, 응답 유실 후 중복 방지, 관리자 전용 조회·수정, 복사 시 문단 유지, 반영완료 체크·해제와 미저장 본문 보존을 확인했습니다. 운영 사이트 배포 성공과 D1의 manuscripts.included 열 적용을 확인했습니다. 실행 환경의 외부 도메인 네트워크 제한으로 운영 URL에 직접 HTTP 요청하는 최종 접속 시험은 수행하지 못했습니다. 최초 관리자 인증은 선생님이 실제 사이트에서 한 번 진행해야 합니다.

## 목차별 편집 완료 원고 일괄 복사

관리함에서 목차 탭을 고르고 **편집 완료 원고 일괄 복사 (N편)**를 누릅니다. 현재 검색·학년·반 조건에 맞는 저장된 원고 중 검토 상태가 ‘편집 완료’인 원고만 포함합니다. 반영완료 체크 여부는 복사 대상에 영향을 주지 않으며, 복사하더라도 검토 상태·체크 값은 변경하지 않습니다. ‘전체 원고’ 탭에서는 목차 설정 순서로 묶고, 각 목차 안에서는 목록 표시 순서를 유지합니다. 원고 사이에 빈 줄을 추가하고 각 원고의 메타정보·본문 문단·줄바꿈을 보존합니다. 작성 중인 수정사항이 있으면 먼저 저장하도록 안내합니다. 자동 클립보드 접근이 제한되면 수동 복사 상자를 표시합니다.

## 원고 접수 중지·재개

관리함 맨 위 **원고 접수 관리 → 원고 접수 중지** 스위치를 켜면 새 원고를 받지 않고, 끄면 기존 제출 링크로 접수를 재개합니다. 설정은 공용 저장소에 저장되어 다른 기기와 새로고침 후에도 유지됩니다. 이 기능 추가 자체로 운영 중인 접수를 중지하지 않으며, 저장된 설정이 없으면 기존처럼 접수합니다.

학생 화면은 접수 중지 안내를 표시하고 새 제출 버튼을 비활성화합니다. 상태는 주기적으로 및 탭 복귀 시 갱신합니다. 상태 갱신 전의 오래된 화면이나 직접 요청으로도 우회할 수 없도록 서버가 새 원고를 기록하는 SQL에서 중지 여부를 함께 검사합니다. 중지 직전에 이미 저장된 원고의 접수 번호 재확인은 허용해 중복 기록 없이 결과를 확인할 수 있습니다.

중지 중에도 입력한 글은 유지하고 복사할 수 있습니다. 중지 응답으로 미접수가 확정되면 초안의 잠금을 풀어 계속 교정할 수 있게 합니다. 기존 원고의 관리자 조회·수정·목차별 복사·반영완료 표시는 계속 가능합니다. 설정 변경은 관리자만 할 수 있으며, 여러 관리자 창의 접수 상태 변경이 충돌하면 최신 상태를 다시 확인하도록 안내합니다.

추가 검증: 서버 테스트 총 14개 통과. 실제 로컬 SQLite와 Chromium에서 관리자 권한, 중지 설정 저장, 화면 새로고침, 기존 학생 화면의 서버 거부와 초안 유지, 새 학생 화면 안내, 중지 중 일괄 복사, 같은 링크로 재개 후 제출을 확인했습니다. 최초 상태 확인과 저장 사이에 접수를 중지하는 경합도 SQL 수준에서 차단하는 테스트를 통과했습니다.
