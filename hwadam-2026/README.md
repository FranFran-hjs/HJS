# 2026 화담집 편집실 — 설치·운영 설명서

학생 편집위원이 원고 사진을 글자로 변환하고 직접 교정하여 제출하는 Google Apps Script 웹앱입니다. 관리자는 목차별로 원고를 찾아 수정하고 한글(HWP)에 붙여넣을 수 있습니다. 별도 서버나 유료 API를 사용하지 않습니다. Google 서비스 사용량 한도와 학교 정책은 적용됩니다.

**이 코드는 실제 Apps Script용 구현입니다. 설치 전에는 학교 웹앱 주소가 생기지 않습니다. 학교 계정에서 아래 설정과 배포를 마쳐야 사용 가능합니다.** 자동 테스트는 모의 Google 서비스와 실제 Chromium으로 수행했습니다. 학교 계정의 실제 OCR, OAuth 동의, 동시 실행과 HWP 붙여넣기는 아래 현장 점검을 마쳐야 합니다.

## 1. 준비물

- 학교 Google Workspace의 교사 계정. 가능하면 실제 운영을 맡을 계정으로 설치하세요.
- 같은 학교 도메인의 학생 계정. 예: 교사·학생 이메일이 모두 `@school.example`로 끝나는 환경.
- Google Sheets, Drive, Docs, Apps Script 사용 허용.
- 학교 관리자에게 Apps Script 웹앱의 **학교 도메인 내부 접속**, Drive API와 Sheets API 사용 및 요청 OAuth 범위 허용 여부를 확인하세요.
- 개인 Gmail이나 외부 계정 공개 배포용 앱이 아닙니다. 학교 계정 확인에 실패하면 접근을 차단합니다.

## 2. 저장용 Google Sheets 만들기

1. 운영 교사 계정으로 [Google Sheets](https://sheets.google.com)에 접속합니다.
2. 빈 스프레드시트를 만들고 이름을 `2026 화담집 원고`로 정합니다.
3. 주소에서 `/d/`와 `/edit` 사이 문자열을 복사합니다. 이것이 스프레드시트 ID입니다.
4. **공유 → 일반 액세스 → 제한됨**을 확인합니다. 학생에게 이 시트를 공유하지 않습니다. 필요하면 담당 교사만 별도로 공유합니다.
5. `원고`라는 탭은 설치 함수가 자동으로 만듭니다. 기존 빈 `시트1`은 그대로 두거나 삭제해도 됩니다.

## 3. Apps Script에 파일 넣기

1. [Apps Script](https://script.google.com)에 운영 교사 계정으로 접속하고 **새 프로젝트**를 만듭니다.
2. 프로젝트 이름을 `2026 화담집 편집실`로 변경합니다.
3. 기본 `Code.gs` 내용을 모두 지우고 이 저장소 `src/Code.gs` 전체를 붙여넣습니다.
4. 왼쪽 **파일 + → HTML**에서 파일 이름을 `Index`로 입력합니다. `Index.html`이 생기면 `src/Index.html` 전체를 붙여넣습니다. 이름의 대소문자를 맞춥니다.
5. 왼쪽 **프로젝트 설정(톱니바퀴)**에서 **편집기에 appsscript.json 매니페스트 파일 표시**를 켭니다.
6. 편집기로 돌아와 `appsscript.json`의 내용을 이 저장소 `src/appsscript.json` 전체로 교체하고 저장합니다.
7. 매니페스트에는 고급 서비스 **Drive API v3**, **Google Sheets API v4**와 서울 시간대가 선언되어 있습니다. 왼쪽 서비스 목록에서도 두 서비스가 등록되어 있는지 확인합니다.
8. 표준 Google Cloud 프로젝트를 직접 연결했다면 해당 프로젝트의 **API 및 서비스 → 라이브러리**에서 **Google Drive API**, **Google Sheets API**도 사용 설정합니다. Apps Script의 기본 Cloud 프로젝트는 고급 서비스 추가 시 보통 자동 설정됩니다.

Drive v2의 `Drive.Files.insert`, `convert:true`, `ocr:true` 코드를 추가하지 마세요. 이 앱은 Drive v3의 `Drive.Files.create`를 사용합니다.

## 4. 비밀번호와 저장소 설정

**프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**에서 아래 네 가지를 입력합니다. 속성 이름은 정확히 입력하세요.

| 속성 이름 | 입력할 값 |
|---|---|
| `SPREADSHEET_ID` | 2단계에서 복사한 시트 ID |
| `ALLOWED_DOMAIN` | 학교 이메일의 @ 뒤 도메인. `@`나 `https://` 없이 입력 |
| `EDITOR_PASSWORD` | 편집위원 공용 비밀번호. 추측하기 어려운 12자 이상 |
| `ADMIN_PASSWORD` | 관리자 전용 비밀번호. 편집위원 비밀번호와 다른 12자 이상 |

비밀번호를 Code.gs, Index.html, GitHub, 시트에 적지 마세요. 이 구현은 요청에 따라 Script Properties에 비밀번호를 저장하며, 스크립트 편집 권한이 있는 사람은 속성을 볼 수 있습니다. 학생에게 프로젝트 편집 권한을 주면 안 됩니다.

## 5. 최초 설치 실행

1. 저장한 후 편집기 상단 함수 선택 메뉴에서 **`setup_`**를 고르고 **실행**합니다. 끝의 밑줄도 함수 이름의 일부입니다. 함수가 안 보이면 저장 후 편집기 새로고침을 해보세요.
2. 운영 교사 계정으로 권한 요청을 확인합니다. 학교가 차단하면 학교 관리자에게 허용을 요청합니다. 차단 경고를 우회하여 공개 계정으로 설치하지 마세요.
3. 실행 로그에 설정 완료가 나오면 다음이 준비됩니다.
   - 시트 `원고`와 지정된 11개 열
   - `화담집_OCR_임시_비공유` Drive 폴더
   - Script Property `OCR_FOLDER_ID`
   - 매시간 동작하는 `cleanupOcr_` 정리 트리거
4. Drive에서 임시 폴더의 공유를 **제한됨**으로 확인하고 학생과 공유하지 마세요.
5. Apps Script 왼쪽 **트리거**에서 `cleanupOcr_`가 한 개 있는지 확인합니다. 설치 함수를 다시 실행해도 같은 트리거를 중복 생성하지 않습니다.

웹브라우저에서 `setup_`나 정리 함수 등 밑줄로 끝나는 내부 함수를 실행할 수 없습니다. 편집기에서 운영 교사만 실행합니다.

## 6. 학교 내부 웹앱 배포

1. 오른쪽 위 **배포 → 새 배포 → 유형 선택(톱니바퀴) → 웹 앱**을 선택합니다.
2. 설명: `화담집 최초 배포`.
3. **다음 사용자 인증 정보로 실행 / 실행 사용자: 나(운영 교사)**를 선택합니다. 이렇게 해야 학생에게 시트·임시 폴더 권한을 주지 않고 저장·OCR을 처리할 수 있습니다.
4. **액세스 권한: 학교 조직 내부 사용자**를 선택합니다. UI의 표현은 학교 설정에 따라 다를 수 있습니다. **모든 사용자/익명/외부 공개로 배포하지 않습니다.** 학교 내부 옵션이 없으면 관리자에게 문의합니다.
5. 배포하고, 끝이 `/exec`인 **웹 앱 URL**을 복사합니다. 학생과 관리자 모두 이 주소 하나를 사용합니다. `/dev`는 개발자 테스트용이므로 학생에게 보내지 않습니다.
6. 같은 도메인의 실제 학생 계정으로 별도 브라우저 프로필에서 접속하고 편집위원 비밀번호를 입력합니다.
7. 운영 교사는 같은 URL에 관리자 비밀번호를 입력합니다.

이 앱은 매 요청에서 `Session.getActiveUser().getEmail()`로 학교 계정을 확인합니다. 같은 Workspace 도메인과 운영 교사 실행 방식에서 보통 확인할 수 있지만, 학교 정책에 따라 빈 값일 수 있습니다. 빈 값이면 앱은 의도적으로 거부합니다. 이 경우 Google Workspace 관리자에게 웹앱 사용자 식별 정책을 확인해 달라고 요청하세요. 계정 확인 코드를 제거하거나 시트를 학생에게 공개하는 방식으로 해결하지 마세요.

## 7. 편집위원 사용법

1. 목차를 선택합니다. 학년·반은 선택 항목이고, 작성자·담당 편집위원·제목·본문은 필수입니다.
2. 사진은 선택 사항입니다. JPG·PNG·WebP를 최대 5장 선택합니다. HEIC는 휴대전화에서 JPG로 바꿔주세요.
3. 원본 장당 20MB 이하만 받습니다. 기기에서 긴 변 2,200px 이하, 2MB 이하 JPG로 자동 압축한 뒤 서버로 보냅니다. 서버도 JPG 형식과 용량을 검사합니다.
4. 여러 장은 원본 미리보기에 보이는 순서대로 변환합니다. 사진을 다시 선택하면 기존 선택을 교체합니다.
5. **글자 변환하기**를 누릅니다. 오른쪽에 이미 글이 있으면 확인 후 그 뒤에 추가합니다. 기존 글을 덮어쓰지 않습니다.
6. 원본과 비교하여 오탈자와 줄바꿈을 직접 수정합니다. 본문은 최대 40,000자입니다. 더 긴 글은 원고를 나누어 제출하세요.
7. 인식이 안 된 부분은 직접 입력합니다. 사진 없이 처음부터 타이핑하여 제출할 수도 있습니다.
8. **원고 제출하기**를 누르고 성공 문구와 접수 번호를 확인합니다.
9. 성공한 뒤에는 같은 버튼으로 재제출할 수 없습니다. **다음 원고 작성하기**로 새 원고를 시작합니다.

**실패 시 초안 보존:** 입력할 때 이 탭의 sessionStorage에 텍스트와 접수 번호를 저장합니다. 사진·비밀번호·세션 토큰은 저장하지 않습니다. 브라우저 저장 차단, 탭 닫기, 기기 변경까지 보존을 보장하지 않으므로 긴 원고는 **원고를 TXT로 보관**하세요. TXT에는 학생 글이 포함되므로 공용 기기에 남기지 마세요.

**제출 결과가 불확실할 때:** 제출한 내용과 접수 번호를 고정하고 **제출 확인·재시도**를 표시합니다. 같은 번호로 다시 요청하여 행을 중복 생성하지 않습니다. 확인 전 내용 변경은 잠깐 잠깁니다. 계속 실패하면 TXT를 보관하고 교사에게 접수 번호를 알려 시트에서 확인하게 하세요. 서버가 요청을 받았을 가능성이 있으므로 별도 새 원고를 바로 만들지 않습니다.

## 8. 관리자 사용법

- 상단에 전체·검토 대기·편집 완료 원고 수가 표시됩니다.
- 전체와 각 목차 탭에 해당 목차의 원고 수가 표시됩니다. 검색 후에도 탭 숫자는 해당 목차 전체 원고 수입니다.
- 작성자·제목 검색과 학년·반 필터를 함께 사용합니다. 제목을 눌러 원고를 엽니다.
- 목차·학년·반·작성자·담당 편집위원·제목·본문을 수정한 뒤 **원고 수정 및 저장**합니다.
- **편집 완료**, **검토 대기로 되돌리기**는 현재 수정사항도 함께 저장합니다.
- **전체 복사**는 현재 화면의 제목 → 학년/반/작성자 → 빈 줄 → 본문 순서로 복사합니다. 본문의 문단과 줄바꿈을 유지합니다. 한글에서 `Ctrl+V`로 붙여넣으세요. HWP 파일 생성·변환 기능은 아닙니다.
- 브라우저가 자동 복사를 막으면 아래 수동 복사 상자가 열립니다. 선택된 글을 `Ctrl+C` 또는 모바일의 복사 메뉴로 복사합니다.
- 다른 관리자가 먼저 수정했다면 덮어쓰기를 막습니다. 화면의 글을 먼저 복사해 보관하고 목록을 새로고침한 뒤 반영하세요.
- 시트에서 직접 고친 내용은 **목록 새로고침** 후 표시됩니다. 열 이름·순서·원고 ID를 변경하거나 중복 생성하면 안 됩니다. 학생 운영 중에는 원고 수정을 앱에서 수행하세요. 웹앱의 잠금은 시트에서 직접 하는 동시 편집까지 막지 못합니다.

## 9. OCR의 실제 지원 범위와 사진 삭제

구현 방식은 **Drive API v3 `files.create`**에 JPG를 업로드하면서 대상 MIME을 `application/vnd.google-apps.document`, 언어 힌트를 `ocrLanguage: 'ko'`로 설정하는 Google Docs 가져오기입니다. 변환한 Docs를 `DocumentApp`으로 읽습니다. 원본 이미지를 별도의 Drive JPG 파일로 만들지 않습니다. 변환 Docs에는 원본 이미지가 포함될 수 있으므로 이것도 삭제 대상입니다.

- 한국어 손글씨 전용 인식 모델이나 정확도 보장은 아닙니다. `ko`는 언어 힌트입니다. 실제 필체와 촬영 환경에 따라 누락·오인식·빈 결과가 생길 수 있습니다. Google Docs가 제공하지 않는 기능을 추가 API 없이 보장하지 않습니다.
- 생성된 임시 Docs는 성공·실패와 관계없이 **변환 요청 종료 시 영구 삭제**를 시도합니다. 교정은 브라우저의 원본 미리보기로 하므로 제출 때까지 Drive 문서를 유지할 필요가 없습니다.
- 삭제 실패나 실행 강제 종료로 남은 문서는 매시간 트리거가 전용 폴더의 `hwadamOcr` 태그가 있고 생성 후 1시간 이상 지난 문서만 다시 영구 삭제합니다. 보통 최대 약 2시간 후 정리되지만, 트리거·Google 서비스 장애가 있으면 더 지연될 수 있습니다.
- 원고 제출 성공 시 브라우저의 사진 데이터와 초안도 지웁니다. 원고 시트에는 이미지·파일 링크를 저장하지 않습니다.
- Google의 관리상 보존 정책, Vault, 서비스 로그나 백업까지 앱에서 삭제하거나 보존 기간을 통제할 수는 없습니다. 학교 보존 정책은 별도로 확인하세요.
- 한 계정당 시간별 OCR 30회, 동시 OCR 1회를 CacheService로 완화 제한합니다. 캐시가 조기 소멸할 수 있어 강제 과금 방지용 한도는 아닙니다. Google 자체 사용량 제한이 우선 적용됩니다. 앱 단위 업로드 선택은 5장, 서버는 페이지 번호 0~4와 장당 용량을 검사합니다.

## 10. 보안과 운영상 주의

- 공용 비밀번호는 개별 편집위원을 식별하거나 학생별 접근을 취소하지 못합니다. 작성자·편집위원 이름은 직접 입력값이므로 본인임을 보증하지 않습니다. 비밀번호 유출 시 해당 역할의 비밀번호를 교체하세요.
- 학교 도메인에 속하면서 관리자 비밀번호를 아는 사람은 관리자가 될 수 있습니다. 따라서 관리자 비밀번호를 편집위원에게 전달하면 안 됩니다. 이 앱은 관리자 개인 이메일 허용 목록 기능을 제공하지 않습니다.
- 매 요청마다 학교 도메인·세션·역할을 서버에서 검증합니다. 편집위원은 전체 원고 조회·수정을 요청해도 거부됩니다. 다른 학생의 제출 내용을 반환하는 API는 없습니다.
- 세션은 브라우저 메모리에만 있고 최대 2시간 유지됩니다. CacheService 조기 만료 시 더 일찍 다시 로그인해야 합니다. 재로그인 창에서도 원고는 유지됩니다. 비밀번호를 변경하면 해당 역할의 기존 세션도 무효가 됩니다.
- 로그인 추측 시도는 계정별 10회/10분의 캐시 기반 제한을 둡니다. 전문적인 공격 방어 장치나 개인별 계정 권한 관리 시스템의 대체재는 아닙니다.
- 학생 이메일은 학교 계정 확인에만 사용하고 시트에 저장하지 않습니다. 세션·횟수 제한 캐시에 해시값이 일시적으로 사용됩니다. 필요한 정보만 입력하세요.
- 시트 입력은 Sheets API의 `RAW` 모드이므로 `=...` 원고가 수식으로 실행되지 않습니다. 화면은 학생 입력을 HTML로 삽입하지 않고 텍스트로 표시합니다.
- Google Docs로 읽기와 임시 파일 삭제를 위해 Drive/Docs 범위, 시트 기록을 위해 Sheets 범위, 트리거 설치와 사용자 확인을 위한 범위를 요청합니다. Drive 범위는 넓은 권한이므로 운영 교사와 학교 관리자만 프로젝트를 관리하세요. 서비스 계정 키나 API 키는 필요 없습니다.
- Script Properties·원고 시트·OCR 폴더는 자동으로 GitHub에 올라가지 않습니다. 사진, 초안 TXT, 시트 다운로드본을 저장소에 올리지 마세요. 공개 저장소에는 소스 코드만 보관합니다.

## 11. 목차 변경

`src/Code.gs` 맨 위 **`CONFIG.categories`** 배열 한 곳만 고칩니다. 예:

```js
categories: ['상상과 창작', '학교생활 경험', '반별 워드클라우드', '새 목차'],
```

변경 코드를 Apps Script에도 반영하고 **배포 → 배포 관리 → 수정(연필) → 버전: 새 버전 → 배포**합니다. 같은 배포를 수정하면 `/exec` 주소를 유지합니다. 접속자는 새로고침 후 다시 로그인합니다.

기존 원고의 목차 문자열은 자동 변경하지 않습니다. 목록에는 이전 목차도 나타나며 관리자가 새 목차로 옮겨 저장할 수 있습니다. 제거된 목차를 그대로 둔 원고는 유효한 새 목차를 골라야 저장됩니다. 미제출 초안도 새 목차를 선택해야 합니다.

| 원고 제출 후 오류 | 화면을 닫지 말고 같은 번호로 재시도. 계속 실패하면 TXT 보관 후 관리자에게 접수 번호 확인 |

| 문단·줄바꿈이 달라짐 | 한글의 붙여넣기 형식과 문단 스타일 확인. 클립보드는 일반 텍스트이며 글꼴·들여쓰기 서식은 별도 적용 |

## 14. GitHub와 다른 기기에서 이어서 작업

코드 구성:

```text
hwadam-2026/
  src/Code.gs             서버·인증·시트·OCR·목차 설정
  src/Index.html          로그인·편집위원·관리자 화면
  src/appsscript.json     Apps Script 서비스·권한
  README.md               교사용 설치 설명서
  TEST_REPORT.md          검증 범위·결과
  tests/                  서버·브라우저 자동 테스트
  package.json            테스트 명령
  .clasp.json.example     선택적 개발 도구 설정 예시
  .gitignore
```

**코딩 도구 없이:** GitHub에서 이 폴더를 열어 파일 내용을 확인하고 Apps Script에 붙여넣으면 됩니다. 다른 기기에서는 같은 Google 계정으로 Apps Script 프로젝트에 접속하여 수정합니다. 변경한 코드는 GitHub 파일 편집 화면에서도 같은 내용으로 저장하세요. **GitHub 저장만으로 Apps Script가 자동 갱신되지는 않습니다.** Apps Script에서 새 버전을 배포해야 사용자에게 반영됩니다. GitHub Pages로 이 HTML만 올리면 `google.script.run` 서버가 없으므로 동작하지 않습니다.

**개발자용 선택 사항 — clasp:** Node.js 설치 후 학교에서 Apps Script API와 clasp OAuth 사용을 허용하는 경우만 사용합니다.

1. 저장소를 clone한 후 `hwadam-2026` 폴더로 이동합니다.
2. `.clasp.json.example`을 `.clasp.json`으로 복사하고 Apps Script 프로젝트 설정의 **스크립트 ID**를 넣습니다. 배포 ID가 아닙니다.
3. [Apps Script 사용자 설정](https://script.google.com/home/usersettings)에서 Google Apps Script API를 켭니다.
4. `npx @google/clasp login` 후 운영 계정으로 로그인합니다. 다른 기기도 각각 로그인해야 합니다.
5. 기존 프로젝트를 먼저 보관하려면 `npx @google/clasp pull`을 별도 백업 폴더에서 수행합니다. `pull`은 로컬 파일을 바꿀 수 있습니다.
6. `npx @google/clasp push`는 `src`의 코드 파일을 원격 프로젝트에 반영합니다. 기존 원격 코드를 확인한 뒤 사용하세요. Script Properties와 저장 데이터는 코드 파일이 아닙니다.
7. 배포 관리에서 새 버전을 배포합니다. 필요할 때만 개발자가 clasp 배포 명령을 사용하세요.
8. GitHub에는 `git add hwadam-2026`, `git commit`, `git push`로 코드를 저장합니다. `.clasp.json`, OAuth 로그인 정보, 실제 학생 원고를 커밋하지 않습니다.

서버 테스트: 이 폴더에서 `npm test` (Node.js 18 이상, 추가 패키지 없음).
브라우저 테스트: Playwright와 Chromium이 있는 환경에서 `npm run test:ui`. `PLAYWRIGHT_MODULE`과 `CHROMIUM_PATH` 환경 변수로 설치 경로를 지정할 수 있습니다. 이 테스트의 Google RPC는 모의 응답이며 실서비스 인증 성공을 증명하지 않습니다.
